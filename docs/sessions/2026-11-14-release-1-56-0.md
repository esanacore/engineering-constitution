## Request

Keep going after the index generator merged. Everything left was blocked on
questions carried since 1.55.0, so they were put to the maintainer directly;
the answers set this session's work: prepare 1.56.0.

## Context

Eighteen `constitution/bump-v1.55.0` pull requests are open and unmerged in
the adopters. A 1.56.0 fleet bump supersedes them, and the commits added to
four of those branches (session-log files, CI runner pins, a JDK step) have
to be carried over rather than lost.

## Decisions

- **`docs/sessions` stays in the recommended tier and the log is rolled out
  to all adopters** — maintainer.
- **Session summaries need no approval before commit** — maintainer. They
  record what happened; `docs/MEMORY.md` stays approval-gated.
- **Three learnings recorded in `docs/MEMORY.md`** — maintainer approved:
  bash `${var/#…}` anchoring, pushes to a merged pull request's branch, and
  recommended-tier additions breaking strict-mode adopters.
- **Prepare 1.56.0 now; the agent tags, publishes, and runs the fleet bump
  after merge** — maintainer, for this release.
- **The index check ships in the adopter workflow template in the same
  release as the script** — agent. The earlier plan was to wait a release,
  but the step is guarded on the script existing in the pinned constitution,
  so a template copied from an older pin never runs it, and it is warn-mode.
- **`RELEASES.md` keeps a new recommended file as MINOR** but now says the
  fleet bump must add it for strict-mode adopters — agent. Reclassifying it
  as MAJOR would overstate a one-file gap that the adopter opted into.

## Discoveries

- A question listed in three consecutive Next Steps procedures went
  unanswered each time; asking it as a direct multiple-choice question got
  an answer at once. A decision that blocks agent work should be asked, not
  only listed.
- No dependency changed since 1.55.0: no open Dependabot alerts and
  `npm audit` in `mcp-server/` reports 0.

- The adopters' instruction files are not uniform. Twelve carry the
  template-shaped checklists (anchor: the demo-page or Next Steps rule) and
  took the session-log rule in every Markdown instruction file. Six
  (`AI_Workstation_Blueprints`, `GPU4HIRE_AI`, `claude-drive-bridge`,
  `mfi-mpower-pro-toolkit`, `murderbot-service-core`, `oldGTX1060_newTricks`)
  predate those checklists; there the rule went into `AGENTS.md` and
  `CLAUDE.md` only, after the required-reading list. `.aider.conf.yml` and
  `.continue/config.json` were left alone everywhere: inserting prose into
  YAML and JSON by script is not safe.

## Outcome

Version references moved to 1.56.0 (`VERSION`, `README.md`,
`CONSTITUTION.md`, `demo.html`, `wiki/Home.md`, `mcp-server/package.json`
and the lockfile's two root fields). `CHANGELOG.md` has a dated 1.56.0
section and an empty `Unreleased`. ADR-0007 records the two decisions;
`RELEASES.md` names the strict-mode cost of a new recommended file; the
adopter compliance workflow template runs `build_session_index.sh --check`
in warn mode; `docs/MEMORY.md` has the three approved entries. Full suite
and release checks pass. No tag pushed yet.

Follow-up, same day, after the release pull request merged: `v1.56.0` tagged
on merge commit `7615a92` and published as Latest; `release-tag-alignment`
passed. `bump_adopters.sh` opened 18 `constitution/bump-v1.56.0` pull
requests. Each also adds `docs/sessions/README.md` and `TEMPLATE.md` and the
session-log rule in the instruction files; the three CI fixes from the
1.55.0 branches were cherry-picked across, and the 18 superseded 1.55.0 pull
requests were closed with a pointer to their replacement.
